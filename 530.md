# Cloudflare error 530

Error `530` is an edge/proxy response, not a Django application status. The
exact cause depends on the Cloudflare message or subcode shown with it. Django
may never receive the request, so adding a Django error template will not fix
an edge-to-origin connection problem.

## What to check

1. Save the full error text, requested URL, timestamp and Cloudflare Ray ID.
2. Check Cloudflare **HTTP Traffic** analytics and the security events for the
   affected hostname and time.
3. Confirm the origin is running and reachable from the network path Cloudflare
   uses. For this project, `runserver` on `127.0.0.1` is local-only and is not a
   production origin.
4. Verify the hostname's DNS target and the Cloudflare SSL/TLS mode against the
   origin's actual HTTPS configuration.
5. Compare the request time with the origin, reverse-proxy and firewall logs.
   If the origin has no matching request, investigate the Cloudflare/DNS/
   network path rather than Django views.

Do not publish origin credentials, private keys, tunnel tokens or full
configuration files when sharing logs.
