# Контекст проекта для AI-ассистентов

Этот файл — карта репозитория для нейросетей и разработчиков, которые помогают
поддерживать проект. Перед изменением кода сверяйтесь с реальными файлами:
назначение компонентов описано здесь, но реализация может меняться.

## О проекте

`SOPHISTICATED` — небольшой русскоязычный сайт на Django. В нём есть главная,
каталог продукции с фильтром категорий и модальным окном товара, блог, страница
«О нас», персонал, регистрация и вход, личный кабинет и отзывы. Основное
оформление — тёмное с фиолетовыми неоновыми акцентами.

Ссылка на GitHub Pages в `README.md` ведёт на отдельное статическое превью из
`docs/`. Изменения Django-шаблонов автоматически не меняют это превью.

## Структура

```text
корень/
├── AI_CONTEXT.md              # карта проекта и инструкции для AI
├── README.md                  # краткий запуск и настройки БД
├── docs/                      # статическое превью для GitHub Pages
│   ├── index.html, products.html, ...
│   └── css/style.css          # стили статического превью
└── Al_Ven/                    # Django-проект; здесь manage.py
    ├── manage.py              # команды Django
    ├── db.sqlite3             # локальный файл SQLite; может содержать данные
    ├── Al_Ven/                # конфигурация проекта Django
    │   ├── settings.py        # приложения, БД, безопасность, static/media
    │   ├── urls.py            # маршруты сайта
    │   ├── asgi.py, wsgi.py   # точки запуска ASGI/WSGI
    │   └── __init__.py
    ├── hello/                 # основное приложение сайта
    │   ├── models.py          # сотрудники, категории, товары, отзывы
    │   ├── views.py           # обработчики страниц и запросов
    │   ├── forms.py           # формы регистрации, входа и отзыва
    │   ├── authentication.py  # вход в Django по email
    │   ├── admin.py           # настройка Django Admin
    │   ├── tests.py           # тесты приложения
    │   ├── migrations/        # схема БД и перенос старых аккаунтов
    │   ├── templates/         # HTML-шаблоны Django
    │   └── static/css/
    │       ├── style.css      # стили основного сайта
    │       └── admin.css      # стили админки Jazzmin
    └── islands_app/           # дополнительное приложение-заготовка;
                               # сейчас не включено в INSTALLED_APPS
```

Файлы `__pycache__`, `.pyc`, учебные `.ipynb` и текстовые файлы не относятся к
работающему сайту без подтверждения через импорты и настройки Django.

## Приложение `hello`

### Модели (`hello/models.py`)

- `Person` — сотрудник: имя, фамилия, отчество и возраст.
- `Category` — категория каталога и её описание (`coment`).
- `Products` — товар: имя, цена (`sale`), материал, описание, дата производства,
  остаток (`conter`), категория (`cat_id`), необязательное изображение.
- `Review` — отзыв с оценкой 1–5 и датой публикации.
- Пользователи сайта хранятся в стандартной Django-модели пользователя, а не в
  модели приложения.

### Маршруты (`Al_Ven/Al_Ven/urls.py`)

| URL | Имя | Назначение |
| --- | --- | --- |
| `/` | `index` | Главная страница |
| `/products/` | `products` | Каталог; фильтр через `?category_id=...`; модалка товара |
| `/news/` | `news` | Персонал и поиск по имени |
| `/blog/` | `blog` | Статические статьи блога |
| `/weo/` | `weo` | Страница «О нас» |
| `/reg/` | `reg` | Регистрация пользователя Django |
| `/vhod/` | `vhod` | Вход по email и паролю |
| `/account/` | `account` | Личный кабинет; необходим вход |
| `/vyhod/` | `vyhod` | Выход; POST-запрос с CSRF-токеном |
| `/reviews/` | `reviews` | Просмотр и добавление отзывов |
| `/admin/` | — | Админка Django с Jazzmin |

Обработчики находятся в `hello/views.py`. Модалка каталога и её JavaScript — в
`hello/templates/products.html`; данные в неё передаются через `textContent`.

### Шаблоны

- `base.html` — общий HTML-каркас, навигация, системные сообщения, CSS и блок
  `scripts`.
- `index.html`, `products.html`, `news.html`, `blog.html`, `weo.html`,
  `reviews.html` — страницы сайта.
- `reg.html`, `vhod.html`, `account.html` — регистрация, вход и кабинет.
- Новые страницы должны наследоваться от `base.html` и использовать именованные
  URL (`{% url 'products' %}`), а не жёстко прописанные адреса.

### Авторизация и безопасность

- `UserForm` проверяет email и пароль; новые учётные записи создаются через
  `create_user`, который хеширует пароль.
- `hello/authentication.py` содержит backend аутентификации по email.
- Включён CSRF middleware; все POST-формы должны включать `{% csrf_token %}`.
- Не сохранять и не логировать пароли в открытом виде.
- Не добавлять в Git реальные пароли БД, секретные ключи и другие секреты.
- `hello/migrations/0005_migrate_registered_users.py` переносит прежние записи
  `RegisteredUser` в стандартных пользователей и удаляет старую таблицу. Перед
  миграциями на БД с важными данными нужно создать резервную копию.

## Static и media

- Основные стили Django-сайта: `Al_Ven/hello/static/css/style.css`, подключаются
  через `{% static 'css/style.css' %}` в `base.html`.
- Стили панели администратора: `Al_Ven/hello/static/css/admin.css`.
- Загруженные изображения товаров хранятся под `MEDIA_ROOT/products/`. В DEBUG
  media обслуживается маршрутом из `urls.py`; в production его должен обслуживать
  веб-сервер/хранилище.
- `STATIC_ROOT` — каталог назначения для `collectstatic`; не использовать его
  как исходный каталог статических файлов.

## Настройки базы данных

Настройки находятся в `Al_Ven/Al_Ven/settings.py`. Сейчас по умолчанию выбирается
MySQL; `DB_ENGINE` принимает `mysql` или `sqlite`. SQLite использует файл
`Al_Ven/db.sqlite3`. MySQL использует переменные `DB_NAME`, `DB_USER`,
`DB_PASSWORD`, `DB_HOST`, `DB_PORT` и, опционально, `DB_CONN_MAX_AGE`.

Пароль базы передавать только через окружение, не помещать его в файлы проекта или
эту документацию. Производственные `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`,
`DJANGO_DEBUG` и HTTPS-настройки также задаются переменными окружения.

Настройки локальных копий могут различаться. Перед запуском миграций или
диагностикой подключения проверьте текущие `settings.py` и переменные окружения.
Не переключайте базу и не переносите/удаляйте файл БД без явного согласования.

## Запуск и проверки

Команды выполняются из `Al_Ven/`. В Windows этой рабочей копии виртуальное
окружение доступно по пути `..\\.venv`:

```powershell
$env:DB_ENGINE = "sqlite"  # либо mysql и настроить DB_* переменные
..\.venv\Scripts\python.exe manage.py check
..\.venv\Scripts\python.exe manage.py test hello
..\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
..\.venv\Scripts\python.exe manage.py runserver
```

Не запускать `migrate` на MySQL, пока подключение не проверено и не подтверждено,
какую именно базу предстоит менять. Инструкции по запуску и переменным окружения
также приведены в `README.md`.

## Правила для AI-изменений

1. Сначала изучить актуальный код и `git status`; работать только в рамках запроса.
2. Сохранять незакоммиченные пользовательские изменения; не делать reset/revert
   чужой работы.
3. Следовать Django-паттернам: именованные маршруты, шаблоны с наследованием,
   ORM вместо SQL без необходимости.
4. При изменении моделей обновлять миграции; уже применённые миграции не менять
   без веской причины.
5. Для новой функциональности добавить/обновить тесты и запустить `check` и тесты.
6. Не путать статическое превью `docs/` с работающим Django-сайтом.
7. Если требуются реальные реквизиты БД, внешний сервис или ручное действие,
   сообщить об этом, а не угадывать секреты и параметры.
