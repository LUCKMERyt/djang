# Контекст проекта для AI-ассистентов

Этот файл описывает актуальную идею, архитектуру и правила работы с репозиторием.
Перед изменением кода необходимо сверяться с реальными файлами и текущим
`git status`: рабочая копия может содержать незакоммиченные изменения пользователя.

## Идея проекта

`SOPHISTICATED` — русскоязычная кураторская витрина вещей для осознанного
повседневного выбора. Сайт помогает посетителю не просто найти товар, а понять:

- из чего он сделан;
- для какого сценария жизни подходит;
- есть ли он в наличии;
- кто стоит за его отбором;
- какой опыт уже получили другие посетители.

Главный принцип интерфейса: **меньше случайного шума, больше контекста для
уверенного выбора**. Тексты и новые функции должны поддерживать эту идею, а не
превращать проект в безличный интернет-магазин.

## Модели и данные

- `Person` — участник команды: имя, описание, должность, контакты и изображение.
- `Category` — направление витрины с названием и описанием.
- `Products` — товар: название, цена, материал, дата производства, наличие,
  описание, категория и необязательное изображение.
- `Review` — отзыв с оценкой от 1 до 5 и датой публикации.
- Пользователи хранятся в стандартной модели Django User.

Изображения товаров находятся в `MEDIA_ROOT/products/`, изображения команды — в
`MEDIA_ROOT/people/`. В базе хранится относительный путь к файлу. В DEBUG media
обслуживается Django, а в production должен обслуживаться веб-сервером,
CDN или object storage.

## Шаблоны и стиль

`hello/templates/base.html` — общий каркас, навигация, сообщения, контакты и
подключение CSS. Новые страницы должны наследовать `base.html` и использовать
именованные URL через `{% url %}`.

Основной визуальный стиль — «Ночной склад»: графитовый фон, жёсткие рамки,
заголовки Oswald, цифры IBM Plex Mono и перламутровый градиент как акцент.
Страницы оформлены как накладная: строка документа в `base.html`
(`{% block doc_name %}`), разделы с заголовочной полосой (`.section`),
таблицы позиций (`.doc-table`) и итоговая строка. Цвета и шрифты заданы
переменными в начале `style.css`.
`hello/static/css/style.css` намеренно упрощён: адаптивные `@media`-блоки,
тяжёлые переходы и анимации не используются, компоновка держится на
`flex-wrap`, `min()` и прокручиваемых таблицах. Не возвращать `@media` или
сложные эффекты без отдельного запроса. `admin.css` относится только к админке.

Каталог и команда используют модальные окна на нативном `<dialog>`. Данные
передаются через `data-*` атрибуты и вставляются в DOM через `textContent`; не
заменять это небезопасной вставкой HTML.

## Авторизация и безопасность

- пароли создавать только через `create_user`;
- не хранить и не логировать открытые пароли;
- POST-формы должны содержать `{% csrf_token %}`;
- вход выполняется через backend по email из `hello/authentication.py`;
- секреты БД и Django передавать только через переменные окружения;
- перед production задать собственные `DJANGO_SECRET_KEY`,
  `DJANGO_ALLOWED_HOSTS`, `DJANGO_DEBUG=False` и HTTPS.

## База данных и запуск

Настройки находятся в `Al_Ven/Al_Ven/settings.py`. `DB_ENGINE` принимает
`sqlite` или `mysql`. Для SQLite используется `Al_Ven/db.sqlite3`; параметры
MySQL: `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.

Команды выполняются из `Al_Ven`:

```powershell
$env:DB_ENGINE = "sqlite"
..\.venv\Scripts\python.exe manage.py check
..\.venv\Scripts\python.exe manage.py test hello.tests
..\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
..\.venv\Scripts\python.exe manage.py runserver
```

Не запускать миграции на MySQL, пока не проверены переменные подключения и не
подтверждено, какую базу разрешено менять.

## Правила изменений

1. Сначала изучить актуальные шаблоны, views, модели и `git status`.
2. Не делать `reset`, `revert` или широкое удаление чужих изменений.
3. Сохранять смысл проекта: кураторство, прозрачность и осознанный выбор.
4. Для новых функций использовать ORM, именованные URL и наследование шаблонов.
5. При изменении моделей создавать миграции; уже применённые миграции не менять
   без веской причины.
6. После изменений запускать `manage.py check`, тесты и проверку миграций.
7. Удалять временные изображения и `__pycache__`, созданные проверками, если они
   появились в рабочем дереве.
8. Не трогать `admin.css`, медиафайлы и базу без необходимости для запроса.
